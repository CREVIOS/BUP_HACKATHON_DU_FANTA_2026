1. Tick order (engine.py tick_once): start_events -> process_supply -> process_departures -> process_arrivals -> generate_demand -> resolve_events -> tick++. Allocation POSTed while inst.tick=T departs during processing of T and arrives during processing of T+transit, BEFORE that tick's demand. Effective lead time = transit_ticks.
2. VERIFIED: route_disruption with start_tick=T + allocation POSTed at tick T -> allocation FAILED at departure, depot inventory NOT refunded (fuel destroyed). Must check /v1/events SCHEDULED disruptions (start_tick<=current tick) before POST, and cancel PENDING ones.
3. VERIFIED: DESTINATION_CAPACITY check uses only current station inventory, ignores in-transit. Overflow at arrival is silently destroyed (min(room,qty)). Shipped 3x2400, station received 0/120/2400.
4. VERIFIED: route_disruption/station_outage/depot_constraint with EMPTY id lists do nothing (guide says empty = all). Only demand_spike/shipment_delay/supply_shortfall honour empty = all.
5. depot_constraint is cosmetic (no capacity change). stale_data only adds header, data is actually fresh.
6. SSE only publishes: simulation.tick, allocation.status_changed (ONLY on create/cancel — NOT departed/arrived/failed despite guide), inventory.updated (depot only on create/cancel), simulator.notice. Must poll /v1/allocations for FAILED/ARRIVED.
7. Idempotent replay returns 201 (guide cheat-sheet says 200). Body equality uses float(quantity)== — send integers.
8. Supply arrivals at depot are clipped to depot capacity (excess lost) — keep depot headroom before arrivals.
9. Demand = daily/96 * hour_factor(sim_time.hour) * region_factor * station.demand_multiplier * (1+U(-noise,noise)), noise seeded sha256(seed:tick:station:demand:fuel). All params except jitter are PUBLISHED in guide §8.5/8.6; seed exposed in /v1/instance. Note base is daily/96 regardless of TICK_MINUTES.
10. Dispatch cap counts created_tick==current tick only -> resets every tick; 23k L/tick total vs ~970 L/tick demand — never binding. Station buffers ~ 1 day of demand. 1.0 service is achievable until fuel runs out.
